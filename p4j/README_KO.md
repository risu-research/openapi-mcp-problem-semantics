# RISU Probe P4-J — Causal Evidence Gate (v0.9.10 experimental)

Goal: developer-declared HAR/MCP `pairs.json` remains **CONDITIONAL_MISMATCH** when it compares as legacy LOSS. A signed trusted same-execution boundary receipt tied to the exact HAR and MCP bytes, original call ID, tool name, trace token and four ordered events can **promote** one case to **CONFIRMED_LOSS**.

## One command

```bash
risu-probe analyze ./capture-folder --recovery --format json
```

Result: `causal_gate_v1.summary.CONDITIONAL_MISMATCH` for any apparent loss with only developer pairing. The original `summary.LOSS` and `decision_v1` remain unchanged for backward compatibility and **are explicitly legacy observations, not causal proof**.

To verify an existing witness using independently provisioned trusted recorder public keys *outside* the capture directory:

```bash
risu-probe analyze ./capture-folder --recovery --causal-trust-store ./trusted_recorders.json --format json --fail-on-confirmed-loss
```

`--fail-on-confirmed-loss`: exit 1 only on `CONFIRMED_LOSS`, 0 if none, 2 on bad inputs/signature. Original `--fail-on-loss` retains strict historical behavior (may fail on *conditional* loss); this breaking-risk distinction is documented. For a native capture, SARIF is rejected until severity can reflect the evidence gate, not silently published as a confirmed finding.

## Supported witnessed causality, with necessary caveats

Only `causal_witness.json` generated by an authorized **boundary recorder** can promote. The recorder must document one actual `tools/call` and its response alongside the corresponding HTTP request and response in a single session, in verified sequence, with a shared unpredictable per-call trace token in the observed MCP request arguments and HTTP request headers. It must sign the exact observation document with Ed25519; the verifier matches **original file hashes, per-event content hashes, call and tool IDs, cross-boundary correlation and signature**, using an **operator-selected** public key trust store located outside the capture directory. `cryptography` is an optional dependency needed only to verify such signatures; without it or without an externally selected trust root, promotion is impossible.

Cryptography attests to the *recognized signer's claim*. It does **not** establish the recorder's independence, honesty, correct deployment or real-world production behavior. Trusting the recorder remains an explicit operator decision. A signed `pairs.json` by the same developer without independent authorization should not be accepted as independent evidence. An arbitrary self-signed key included in the capture cannot promote.

## Tested boundaries

- P4-H legacy native capture: original raw LOSS 1, **CONDITIONAL_MISMATCH 1**, confirmed 0.
- P4-G saved P4-D/P4-E cases: original raw LOSS 3, **CONDITIONAL_MISMATCH 3**, confirmed 0 (these archived comparisons do not contain the new independent signed witness).
- P4-I false join pattern: a valid but falsely declared cross-project pair must **never** count as confirmed loss.
- P4-J bounded local real MCP SDK call plus independent recorder: 200 remains witnessed no-loss, intentionally flawed 404 is promoted to **CONFIRMED_LOSS** *only with an authorized signed boundary receipt*. This is a **controlled local test server** (original MCP SDK, no real vendor claims), not an independent developer's production capture.
- Tampered captures/signatures, wrong key, false token, reordered events and reused witness are rejected.

Original test fixture proof-of-concept uses an ephemeral **test** signing key and a corresponding trust file emitted **outside** the capture directory. Do not use that test trust file to authorize production records. No private signing key is shipped or used by the analyzer.

Product main branch is unchanged. Frozen comparator, API contract and field-recovery algorithms are not patched. No external service, LLM, registry or server is contacted by `risu-probe analyze`.
